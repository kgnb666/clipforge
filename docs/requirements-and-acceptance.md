## 1. 文档目的与适用范围

本文档是 ClipForge 后续分阶段实现的**唯一验收依据**：定义 Stage 1 已具备的能力基线、Stage 2（Phase 2A–2D）待实现需求、可测量的验收步骤、四个阶段 Gate 的判定规则与证据要求。

术语约定：
- **验收步骤（前置→操作）**：可复现的最小操作序列，前置写明所需素材与初始状态。
- **证据类型**：必须落盘、可被第三方复核的文件或记录（截图、日志、JSON、哈希、文件清单）。
- **执行方式**：`自动`（可由脚本/单元测试执行）| `人工`（必须人工操作界面或准备素材）| `自动+人工`（两者各留证据）。
- **优先级**：`P0` 阻塞 Gate（不通过不得进下一 Phase）| `P1` 应当完成（延期需在报告中记录）| `P2` 可延后至后续阶段。
- **状态**：`待实现`（功能尚不存在）| `待验收`（能力已存在，需在 Stage 2 重新验证）| `待审批`（依赖开发者决策）| `已批准，待实施`（设计/依赖决策已获用户批准，功能或安装尚未执行——**获批不等于已实现**）。

## 4. 架构与安全需求（ARCH）

> 适用于全部 Phase 2A–2D；验收方式以代码走查 + 单元测试 + 日志检查为准。

| ID | 需求描述 | 验收步骤（前置→操作） | 预期结果 | 证据类型 | 执行方式 | 优先级 | 状态 |
|---|---|---|---|---|---|---|---|
| ARCH-001 | FFmpeg/FFprobe 调用必须使用安全的进程参数传递（`std::process::Command` + `OsString` 参数列表），**禁止**把用户路径拼接进 shell 命令字符串 | 代码走查全部进程调用点；对参数构造函数运行恶意输入单测（如 `; rm -rf`、`&& calc`、`$(...)`、换行、含引号路径） | 恶意字符串仅作为普通参数传入（无 shell 解释）；无 `cmd /c`、`sh -c`、字符串拼接执行路径 | 代码走查记录 + 单测输出 | 自动+人工 | P0 | 待实现 |
| ARCH-002 | 用户文件路径、临时目录、输出路径一律按不可信输入处理 | 走查：路径先规范化（`PathBuf`），校验存在性/类型/可写性；临时/缓存目标必须校验位于应用缓存根内 | 不存在基于路径的越权写入；`..` 等形态不产生越界行为 | 走查记录 + 单测（含恶意路径） | 自动+人工 | P0 | 待实现 |

| ARCH-004 | 命令失败必须保留可诊断信息（退出码 + stderr 尾部，**截断上限 8 KiB = 8,192 字节**，D-0020），日志**不得**写入完整环境变量、API 密钥等敏感信息 | 制造 FFprobe/FFmpeg 失败 → 检查应用日志 | 日志含：命令类别、退出码、stderr 尾部（≤8 KiB）；无环境变量转储、无系统信息泄露 | 脱敏日志样本 | 自动+人工 | P0 | 待实现 |

| ARCH-006 | 前端只显示真实取得的数据与状态：不编造时长/编码/缩略图/成功提示 | 对每个展示字段执行"UI ↔ FFprobe 原始 JSON"逐字段对照；人为制造字段缺失场景 | 缺失字段显示 `N/A` 或错误态，绝无猜测值；无任何假进度/假成功 | 对照证据表（见 P2B-010） | 人工 | P0 | 待实现 |
| ARCH-007 | 复用现有架构；除已批准项外不新增依赖（前端 React/TS、Rust `tauri`/`serde`/`serde_json` 已具备） | 对比 `package.json`/`Cargo.toml` 变更清单与批准记录 | 无未批准的新依赖；无框架替换 | 依赖变更清单 | 自动+人工 | P0 | 待实现 |

## 9. Phase Gate 规则（Gate-2A / 2B / 2C / 2D）

四个 Gate **独立判定、顺序执行**，每个 Gate 必须同时满足以下 9 条规则：

1. 对应 Phase 功能已实现（且仅实现该 Phase 及已通过的先前 Phase 范围）。
2. 该 Phase 的测试**实际执行**并在 `docs/test-report.md`（或阶段报告）中记录结果。
3. 核心成功场景与核心失败场景**均有证据**（截图/日志/JSON/哈希）。
4. **回归测试按 Gate 分层执行**：Gate-2A / Gate-2B / Gate-2C 仅要求**该阶段直接相关的回归测试**（范围见下表 Gate 的"回归范围"备注），**不要求**将 P2D-012 定义的完整 Stage 1 回归作为这三个 Gate 的前置条件；Gate-2D 要求执行 **P2D-012 定义的完整 Stage 1 回归**。P2D-012 仍是完整回归的唯一定义依据，其测试范围不因本条而增减。
5. 无未解决的阻断级（P0）问题。
6. 失败测试不得从报告中删除，也不得通过降低验收标准来规避；修改标准必须先走 §1 变更控制。
7. Gate 不通过时**停止**，不得继续下一 Phase；保留全部证据与工作成果，不做破坏性清理。
8. PASS 必须基于实际测试结果（证据可复核），**不得仅依据执行者自述**。
9. 本准备阶段只冻结标准；任何 Gate 一律**不得提前宣布通过**。

| Gate | 判定范围 | 必需用例 | 备注 |
|---|---|---|---|
| Gate-2A | 导入 | P2A-001 ~ P2A-010、P2D-008、P2D-009 | 依赖（dialog 插件）**已获批（D-0013）**，安装须单独执行授权；**Gate-2A 不依赖 Phase 2B/2C**，可在 2B/2C 未实现时独立验收；**回归范围**：该阶段直接相关的回归测试——窗口显示/响应/关闭/重启（P2D-012 清单中与 2A 相关的子项），**不要求** P2D-012 完整回归 |

## 10. 证据要求（每个 Phase 至少保存）

1. 变更文件清单（新增/修改，含路径）。
2. 实际执行的命令、工作目录、退出码（原始日志）。
3. 每条测试用例的结果与失败原因（失败必须保留）。
4. 关键界面截图（失败态与成功态均需）。
5. FFprobe 原始 JSON 与界面字段对照证据（P2B-010 对照表）。
6. 缩略图文件本身 + 其来源视频与取帧时间记录。
7. 应用日志（脱敏：不含完整环境变量/密钥/无关系统信息）。
8. 阶段实施报告 + `docs/decision-log.md` 更新。

证据目录约定：`docs/evidence/stage2/<phase>/`；测试素材目录：`docs/evidence/stage2/test-assets/`（D-0021）；文件命名包含用例 ID（如 `P2B-003-ui.png`、`P2B-003-ffprobe.json`）。

状态词汇统一（测试报告中必须使用）：`自动化测试通过` / `人工测试通过` / `尚未执行` / `无法验证`。**不得**把计划执行的测试写成已完成，不得把"未执行"标记为 PASS。

### 10.1 受控依赖模拟（工具缺失/无法启动/非零退出；v1.1 新增，适用 P2C-004、P2D-005、P2D-006 等）

1. **禁止**通过重命名、移动、覆盖或删除系统中真实安装的 FFmpeg/FFprobe 来模拟缺失。
2. 使用独立测试配置或依赖路径注入：将工具路径指向**专用测试目录**中不存在或不可启动的可执行文件。
3. 必须分别覆盖三种场景：(a) 工具文件不存在；(b) 工具存在但无法启动；(c) 工具启动后返回非零退出码。
4. 非零退出码场景使用**受控测试替身或明确设计的测试入口**模拟，不得修改真实工具。
5. 测试完成后：清除测试覆盖配置、恢复正常探测路径，并**实际验证**正常 FFmpeg/FFprobe 调用仍然可用。
6. 明确禁止修改系统 PATH、注册表、全局环境变量或 WinGet 安装目录。
7. 证据必须记录：测试配置、预期错误分类、实际结果、恢复验证。
8. 测试配置仅限测试构建/测试入口使用，不得成为面向用户的绕过路径；若实现测试替身需要新增依赖：**本次不安装**，优先使用标准库或现有测试能力，确需新增依赖时另行审批（见 §11.2）。

### 10.2 ACL 权限测试规程（专用于 P2A-005；v1.1 新增）

1. 只能使用**专门的测试素材副本**；不得操作用户原始视频、项目目录或系统文件。
2. 修改 ACL 前记录：目标文件路径、原 ACL、当前用户身份、文件哈希。
3. 使用**最小范围**的 ACL 变更（单文件、拒绝当前用户读取）。
4. 测试后**无论成功还是失败**，都必须执行恢复流程。
5. 恢复后重新读取 ACL 并验证原状已恢复；同时复核文件哈希不变。
6. **如果无法确认恢复成功：立即停止后续测试并报告，不得声称测试通过。**
7. 测试命令必须限定到单个测试文件；**禁止递归修改父目录权限**。
8. 文档修订阶段**不执行任何 ACL 修改**。

### 10.3 受控超时与容量上限验证（P2B-009 / P2D-013 / P2C-006；v1.1 新增）

1. FFprobe 超时验证：允许通过**受控测试配置**注入较短超时值 + 受控延迟测试替身触发超时路径；**不得依赖构造真实 >30 秒的视频**；默认值 30 秒通过配置走查/单元测试断言确认；超时后必须验证子进程终止与无残留（P2D-013）。
2. 缓存上限验证：允许通过**受控测试配置**注入较小容量上限构造超限场景；默认值 200 MiB（209,715,200 字节）通过配置断言确认；不以真实生成 200 MiB 缩略图作为强制测试方式（可作为 P2 可选附加验证）。
3. 所有测试覆盖配置（超时注入、容量注入、依赖路径注入）在测试后必须清除，并验证默认行为已恢复。

### 10.4 测试素材生成（已批准，D-0021；v1.1 新增）

1. 允许使用现有 FFmpeg CLI（系统依赖）生成专用测试素材，**仅用于测试**。
2. 素材仅写入专用测试素材目录 `docs/evidence/stage2/test-assets/`；不得修改 Stage 1 已有证据素材、不得覆盖现有文件。
3. 每个素材必须记录：生成命令、退出码、SHA256、FFprobe 验证结果。
4. 本授权**不**授权实现导入、元数据、缩略图或转码等任何业务功能；文档修订阶段不执行素材生成命令。
